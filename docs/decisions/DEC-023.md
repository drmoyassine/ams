---
id: DEC-023
title: Embeddings rank IQF mapping candidates; vectors are stored in plain PostgreSQL arrays
status: accepted
context: >-
  Mapping an external standard to the IQF is similarity matching between short texts, often across languages (Arabic
  accreditor wording against English IQF wording) and vocabularies. Full-text and trigram search match shared words only.
  Anthropic offers no embedding model, so a second, configurable provider is needed.
decision: >-
  1. An embedding model ranks candidates; it never decides. The shortlist goes to aiExtract, which proposes
     covers / partly_covers / related with a reason, and a person accepts. Similarity scores are internal ranking only,
     never shown as a match, coverage or confidence percentage.
  2. Ranking is hybrid: vector cosine similarity plus trigram/full-text on codes and terms, so exact references
     ("CFR 2.4") still win. The pipeline works with embeddings switched off (lexical only).
  3. One import point: embed(texts) next to aiExtract in packages/core/src/ai, worker-only, temperature-free, logged and
     counted against the same per-run spend limit.
  4. Provider is configurable in Settings → AI, separately from the generation model: an OpenAI-compatible endpoint
     (base URL, model, key, dimension), which covers hosted providers and self-hosted servers (Ollama, TEI) for
     institutions that want no text to leave their network. The model must be multilingual (Arabic).
  5. What may be embedded: framework text only, i.e. requirement code, title and description (external standards and
     the IQF) and their level path. Evidence files, dataset contents, form responses, requests and accreditor letters are
     never embedded. A CHECK constraint on the owner type enforces this in the database.
  6. Storage: an institution-scoped, RLS-protected table (owner type, owner id, model, dimension, text hash, vector as
     real[]). Similarity is computed in packages/core by exact scan. At the expected scale (thousands of items per
     institution) this is fast and needs no PostgreSQL extension; pgvector is an optional later optimisation, not a
     dependency. The table is derived data, outside the frozen-version trigger, rebuildable, and re-embedded only when
     the text hash or model changes.
rationale: >-
  Better recall on paraphrased and cross-language matches, without adding infrastructure or weakening DEC-008
  (host-agnostic) or the "AI proposes, humans publish" rule.
consequences: >-
  Extends DEC-021 (IQF text to AI) to the embedding provider. Step E is measured against a small hand-labelled mapping
  set (shortlist recall at 10, lexical only vs hybrid) before embeddings are on by default.
