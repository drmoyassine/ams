title: >-
  The AMS and the BI may be deployed together in one Compose project, sharing one database (the AMS in schema ams, the
  BI in its own schemas, public reserved for the BI's analytic data) and the object store
status: accepted
context: >-
  The owner wants (2026-10-26) a deployment mode where the AMS and the BI (drmoyassine/ai-native-bi) run in the same
  Compose project and share the same resources. DEC-017 keeps them separate products with their own storage, and the AMS
  calls the BI over HTTPS only. Revised 2026-10-27: the owner prefers one database with a schema per product to a
  database per product, and reserves the public schema for the BI's analytic data.
decision: >-
  Co-deployment is a deployment mode, not a merge. Shared: one PostgreSQL server and ONE database, one Garage store, one
  private network. Separate: each product owns its schemas and roles. The AMS lives in the schema ams (migration 0070
  moves it out of public, sets the database's default search path to ams, and lets only the AMS's roles use the schema);
  the BI owns its own schemas (its operational tables in bi, its job queue in its own schema) and the public schema,
  reserved for its analytic data. No role of one product has any privilege on the other's schemas, no cross-schema
  query, no shared table; they still talk only through the contract over HTTP. Either product still runs alone with the
  same layout (the AMS alone leaves public empty). On the private network the AMS may call the BI over plain http, but
  only the one host named by BI_PRIVATE_HOST, a single label (a Compose service name such as bi-api) that can never name
  a host on the internet; everywhere else https. The combined Compose file lives in the BI repository and builds the AMS
  from its own checkout.
rationale: >-
  One database is one thing to run, back up and monitor for a small institution; schemas with exclusive grants keep the
  ownership of DEC-017 (each product's storage is its own and is dumped or restored with pg_dump -n). Plain http is safe
  only where the address cannot leave the private network.
consequences: >-
  AMS: BI_PRIVATE_HOST (bi-client resolveBiUrl, tested); migration 0070 (schema ams, isolation tested in
  ams-schema.test.ts); the AMS's migrations must run as the database owner or a superuser (ALTER DATABASE ... SET
  search_path). BI: its role created on the AMS's database with its own schemas and search path, its job queue out of
  the AMS's pgboss schema, compose.together.yaml pointing at the shared database (requested through the issue bridge).
