title: The curriculum map is built both ways, top-down and bottom-up, on its own Settings tab; flags, never blocks
status: accepted
context: >-
  The curriculum map was built only from CLO -> PLO links, so a course without CLOs could not be mapped, and the map and
  coverage sat inside each program's Outcomes page. The owner (2026-11-14): move the map and coverage to a stand-alone
  tab between Courses and Learning outcomes, and let a map be built two ways, bottom-up (CLOs -> PLOs) and top-down
  (PLOs -> courses -> CLOs).
decision: >-
  Settings -> Organization has a Curriculum map tab (pick a program; a grid by course and a view by PLO). Top-down, a
  course is mapped directly to a PLO at one level (one level per course and PLO; a course may map to several PLOs),
  stored in course_outcome_map. Bottom-up, its CLOs are linked to the PLO at a level (outcome_link, the same links the
  syllabus edits), and they fill the same cell. Coverage flags a course mapped top-down with no CLO linked to that PLO,
  a top-down level that differs from the highest level its CLOs reach, a course mapped to no PLO either way, and a
  course outside the syllabus rules' minimum and maximum PLOs and CLOs (the same settings). A CLO linked to a PLO the
  course was not mapped to top-down is not flagged. Nothing is blocked, and changes save at once.
rationale: >-
  Programs design their map before CLOs exist; mapping a course first and its CLOs later serves both ways of working
  with one map, and the flags show where the two disagree.
consequences: >-
  Later: courses that serve no PLO will map to ILOs or college or school outcomes instead (the table already accepts an
  ILO target; the screen does not offer it yet); the rules for unmapped courses; approval of map changes belongs to the
  approvals management workstream; importing a map from Excel waits for a sample workbook.
